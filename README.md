# Bank Accounts OOP

Учебный проект: объектная модель банковских счетов на Python.
Демонстрирует принципы ООП: абстракцию, наследование, инкапсуляцию,
собственные исключения и валидацию данных.

## Что реализовано

- **`AbstractAccount`** — абстрактный базовый класс (`ABC`) для всех типов счетов:
  владелец, идентификатор, защищённый баланс, статус, общие проверки,
  заморозка / разморозка / закрытие. Абстрактные методы: `deposit`, `withdraw`, `get_account_info`.
- **`BankAccount`** — конкретный счёт:
  - автоматическая генерация короткого UUID, если номер не передан;
  - валюта: `RUB`, `USD`, `EUR`, `KZT`, `CNY`;
  - `__str__` (для пользователя, номер замаскирован) и `__repr__` (для разработчика).
- **Статусы счёта** (`Enum`): активный, замороженный, закрытый — с контролем допустимых переходов.
- **Собственные исключения** с общим родителем `AccountError`.
- **Валидация**: тип и знак суммы, начальный баланс, статус, валюта.
- **Инкапсуляция**: `balance`, `status`, `account_id`, `currency` доступны только для чтения через `@property`.

## Как запустить

Требуется Python 3.10+. Внешние библиотеки не нужны.

```bash
python src/main.py
```

## Пример использования

```python
from models import BankAccount
from enums import Currency

acc = BankAccount("Дарья", 1000, currency=Currency.USD)
acc.deposit(500)
acc.withdraw(200)
print(acc)
# BankAccount | клиент: Дарья | счёт: ****3f2b | статус: active | баланс: 1300 USD
```

## Проектные решения

- **Иерархия исключений.** Все ошибки наследуются от `AccountError`. Вызывающий код
  может ловить конкретную ошибку (`InsufficientFundsError`) или любую ошибку счёта сразу (`AccountError`).
- **Порядок проверок в операциях:** статус счёта → корректность суммы → достаточность средств → изменение баланса.
  Сначала все проверки, потом изменение состояния — объект никогда не остаётся в некорректном состоянии.
- **Замороженный счёт** блокирует и пополнение, и снятие: любые движения средств требуют разморозки.
- **Закрытый счёт** — конечное состояние: его нельзя разморозить или заморозить повторно.
- **Закрыть можно только счёт с нулевым балансом**, чтобы средства клиента не «потерялись».
- **Генерация id через `account_id=None`**, а не через значение по умолчанию `uuid4()`:
  default вычисляется один раз при определении функции, и все счета получили бы одинаковый id.
- **Ответственность классов.** `AbstractAccount` хранит общее (id, баланс, статус, проверки),
  `BankAccount` добавляет специфичное (генерацию id, валюту, формат вывода).
- **`_`-атрибуты + read-only `@property`.** Баланс меняется только через `deposit`/`withdraw` с проверками.
  Подчёркивание — соглашение Python, а не жёсткая защита.
